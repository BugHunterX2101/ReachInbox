# CareerOps research bridge

Python-only HTTPS service intended for the existing Lovable **Career Research Bridge** UI.

Deploy this folder on Render as a **separate Docker web service** with branch `careerops-research-bridge`, root directory `careerops_bridge`, `/healthz` health check, and auto deploy OFF. This branch does not affect either existing ReachInbox production service tracking the `main` branch.

Required Render secret: `CAREEROPS_BRIDGE_TOKEN` (generated by Render, at least 32 random characters). Use the same secret as Lovable's server-only `CAREEROPS_PYTHON_BRIDGE_TOKEN`; set Lovable's `CAREEROPS_PYTHON_BRIDGE_URL` to this Render service's HTTPS origin. These secrets must never enter GitHub code or browser JS.

`GET /healthz` exposes real installation detection, not a success claim for upstream execution.
`POST /v1/collect` requires header `X-CareerOps-Token` and JSON `{"max_sources":2}`. It returns at most three candidate JobPosting records, **HOLD** only. Does not call Google Sheets or Gmail; no scheduler or draft writer.
Two public employer job pages are static reviewed seeds. Every page must pass robots checks, no redirects, no login/captcha, size/time cap and HTTP 200 with HTML. No crawling of unknown URLs or personal profiles.

Scrapling parses public Schema.org JobPosting JSON-LD. ScrapeGraphAI can be used only with a local Ollama model explicitly enabled, never paid API. Agent Reach uses its official CLI in anonymous `public-web` mode and stores only discovery text, never private profiles or contact emails. It may be disabled if setup is incomplete.

Render free services can spin down, and /tmp SQLite is ephemeral. The existing Apps Script's company-level suppression and dedup remain the real handoff gate. Avoid running a separate scheduler. Completion requires real /healthz, source scan logs, Lovable secrets and an existing Apps Script HOLD readback; no synthetic READY records.
